# Web Image Uploader 收费模式与商业化需求文档

版本：v1.0 · 日期：2026-09-04 · 状态：**开发基线 → 已实现并通过本机验收**

> 本需求已全部落地：收费后端（`backend/`，Node/TS/Express/TypeORM/MySQL 8）、管理后台（`admin/`，Vue 3/Element Plus/Pinia/Vue Router）、扩展端权益接入（设置页「收费与会员」+ 弹窗额度栏/升级入口）。支付渠道（支付宝 RSA2、微信 APIv3、PayPal Checkout）通过管理后台表单配置并支持连接测试与沙箱/生产回调。详见 [`验收报告.md`](验收报告.md) 与 [`宝塔部署文档.md`](宝塔部署文档.md)。

## 1. 目标与原则

将扩展升级为“网页图片扫描、批量上传 Google Photos、普通下载、ZIP 打包”的可商业化产品。收费系统必须由服务端裁决，扩展只展示状态和发起任务；不得把价格、额度或支付成功状态仅保存在本地。

合规原则：最小权限、明确告知网页访问用途；Google OAuth 仅用于 Google Photos 授权；支付由合规支付服务商处理；不保存银行卡/支付密码；图片中转默认不持久化，任务完成后自动清理；提供隐私政策、服务条款、退款与账号删除入口。

### 图片数据保留政策

服务端中转默认不把图片写入数据库或对象存储。单张代理接口在内存中流式读取并返回；ZIP 任务如因打包库需要临时文件，只允许写入隔离临时目录，任务完成、失败或超时后立即删除，最长保留 10 分钟。日志不得记录完整图片 URL 的查询参数、图片内容或可还原的二进制。若未来增加“云端保存/历史下载”功能，必须单独取得用户明确同意、提供开关、删除入口和新的隐私政策说明。

## 1.1 技术路线（以 GitHub 最新项目为准）

参考 `shushuhao01/CRM` 最新代码，平台后端采用 **Node.js 22 + TypeScript + Express + TypeORM + MySQL 8**，管理后台采用 **Vue 3 + TypeScript + Element Plus + Pinia + Vue Router**，在宝塔面板使用 PM2/Nginx 部署。参考 `shushuhao01/Nova-key` 的支付实现，吸收支付宝 RSA2、微信支付 APIv3、Webhook 幂等、主动查单和退款状态机设计。

宝塔是部署面板，不限定必须使用 PHP；本项目优先沿用 CRM 的 Node/TypeScript 路线，以便复用实体、服务层、中间件、权限和后台 UI 规范。若后续确定必须 PHP，将按同一 API 契约重新实现，不能直接复制 Node/Java 代码。

## 2. 功能计费单位

一次“任务”计一次机会，而不是每张图片计费：

| operation | 说明 |
|---|---|
| upload | 批量上传到 Google Photos；按一次提交任务计费 |
| download | 批量下载选中图片；按一次下载任务计费 |
| zip | 服务端抓取并生成 ZIP；按一次打包任务计费 |

任务创建前服务端预扣额度；任务因服务端错误取消时自动退回。用户主动取消、源站拒绝、超出文件限制不自动退回，界面必须展示原因和规则。

## 3. 免费与付费规则

默认免费方案：每个账号每月 upload/download/zip 各 1 次；每次最多 10 张、单张 20MB、ZIP 200MB。管理员可配置，不得在客户端硬编码。

套餐支持：月度订阅、年度订阅、永久授权、额外次数包。每个套餐可配置价格、币种、周期、任务次数、单次张数、流量上限、并发上限、是否允许 ZIP/服务端中转、试用期和退款策略。

额度优先级：赠送额度 → 套餐额度 → 次数包；过期额度不可使用。永久授权也受公平使用、反滥用和服务器资源限制约束。

## 4. 支付渠道

首期抽象统一支付接口，按地区启用渠道：

- 微信支付：Native/扫码或 H5，需企业主体、商户号、API v3 密钥、证书和回调域名。
- 支付宝：电脑网站/手机网站或当面付，需商户主体、应用公钥/私钥和异步通知地址。
- PayPal：Checkout Orders + Webhook，支持国际卡和 PayPal 钱包。
- Stripe/Paddle/Lemon Squeezy：作为国际订阅和税务处理备选。

支付渠道均由服务端创建订单，客户端只打开支付页面或展示二维码；支付成功以服务端验签和 Webhook 为准，禁止以前端回调参数直接开通权益。订单必须幂等，重复 Webhook 不得重复发放额度。

## 5. 账号与授权

用户需登录产品账号才能使用免费额度、服务端 ZIP、订阅和跨设备同步。推荐“Google 登录/邮箱验证码”作为产品账号登录；Google Photos OAuth 作为独立授权，可重新授权、撤销和更换账号。不得把 access token 当作付费凭证。

服务端保存：用户 ID、邮箱、套餐、额度、订单号、支付平台客户 ID、审计时间。不得保存 Google 密码、银行卡号或长期保存图片内容。

## 6. 服务端 API

统一返回 `{ok, code, message, requestId}`，所有接口需要 HTTPS、产品登录令牌和幂等键。

- `GET /api/v1/me`：账号、套餐、额度、过期时间。
- `GET /api/v1/plans`：公开套餐和价格。
- `POST /api/v1/entitlements/reserve`：预扣一次任务额度。
- `POST /api/v1/entitlements/commit`：任务成功确认扣除。
- `POST /api/v1/entitlements/release`：符合规则时退回额度。
- `POST /api/v1/proxy/fetch`：服务端抓取单张图片并流式返回。
- `POST /api/v1/zip/jobs`：创建 ZIP 任务，返回进度和临时下载地址。
- `GET /api/v1/zip/jobs/:id`：查询 ZIP 状态。
- `POST /api/v1/billing/checkout`：创建支付订单。
- `POST /api/v1/billing/webhooks/:provider`：支付平台验签回调。
- `GET /api/v1/billing/orders`：用户订单和发票状态。
- `DELETE /api/v1/account`：删除账号、额度、订单关联数据和临时文件。

中转安全：仅允许 http/https；拒绝 localhost、私网、云元数据地址和非标准危险端口；限制响应大小、超时、重定向次数、并发和内容类型；不跟随用户 Cookie；临时文件加密、短 TTL 自动删除；记录审计但不记录完整图片 URL 查询敏感参数。

## 7. 管理后台

后台必须支持 RBAC（管理员/客服/只读审计），并提供：

- 用户搜索、封禁、删除和额度调整；
- 套餐/价格/币种/周期/免费额度配置；
- 支付订单、退款、争议、Webhook 重放；
- ZIP/中转任务、流量、失败率、并发和成本监控；
- 风控规则：IP/账号/设备限流、异常任务、批量注册；
- 审计日志（谁、何时、修改前后值）；
- 隐私数据导出与删除请求；
- 公告、维护开关和服务状态页。

后台不得展示图片明文，除非用户主动提交工单并明确授权。

## 8. 扩展端新增 UI

设置页新增“账户与权益”：登录/退出、当前套餐、剩余次数、到期时间、刷新权益、管理订阅、订单记录、隐私政策、删除账号。

弹窗新增：

- 顶部显示登录状态和剩余额度；
- 上传、下载、ZIP 按钮点击前显示本次消耗和限制；
- 额度不足时显示套餐卡片和“升级”按钮；
- ZIP 显示抓取中、打包中、下载链接过期、部分失败原因；
- 支付中禁止重复提交，订单状态可恢复查询；
- 明确提示图片可能经过服务端中转。

## 9. 商店审核要求

正式发布前必须使用正式商店扩展 ID 重新配置 OAuth Client；OAuth Consent Screen 切换 Production 并完成 Google Photos 权限审核。商店页、扩展设置页和网站必须提供隐私政策、服务条款、数据删除和客服入口。`<all_urls>` 仅作为可选权限，在用户操作时申请并解释用途；移除不必要权限。不得使用远程代码、隐藏功能、误导性免费按钮或绕过网站访问控制。

## 10. 验收标准

支付成功只能由验签 Webhook 开通；重复回调幂等；余额不足不能创建任务；任务失败按规则退回；跨设备权益一致；账号删除后 Token/临时图片/支付关联数据按保留政策处理；所有敏感操作有审计记录；Mock 支付、Webhook 重放、退款、过期订阅、网络中断、重复点击均有自动化测试。

## 11. 分阶段交付

Phase 1：服务端接口契约、账号/套餐/额度模型、扩展权益 UI、Mock 支付和 ZIP 中转适配。

Phase 2：微信/支付宝/PayPal/国际支付渠道、Webhook、管理后台、隐私政策与商店素材。

Phase 3：真实商户联调、风控、压力测试、Google OAuth 审核和 Chrome Web Store 提交。
