## 追加：上传慢 / CORS 下载失败 / 默认卡片视图（9-4）

用户反馈右键上传1张很久且报 `[CORS] Failed to fetch`，且希望默认卡片视图。根因与修复：
- **慢 & CORS 失败根因**：图片来自 jkforum.net，有严格防盗链（校验 Referer 且跨域限制）。下载链路当前为 content script（隔离 fetch→MAIN world fetch 均 `mode:'cors'`，**仍受 CORS 限制**）→ base64 分块传输（1.5MB/块，慢）。真正能绕过 CORS 的只有 **Service Worker 直连**（需 `<all_urls>` 主机权限），但用户没授权。
- **修复1 主机权限**：`start_upload` 后台（service-worker.js）与 popup `uploadSelected`（手势内 `chrome.permissions.request`）都尝试申请 `<all_urls>`；有了它 SW 直接二进制 fetch，跳过 base64 分块，快且成功。
- **修复2 CORS 指引**：任务视图检测到 failed+errorCode==='CORS' 时，渲染「授予所有网站下载权限后重试」按钮（调 ensureHostPerms + retry_failed 整批重试）+ 说明文案。README FAQ 同步更新「先授权再重试」。
- **修复3 默认卡片视图**：`state.layout` 默认改为 `'grid'`；`initLayout()` 在 boot 同步视图按钮高亮。grid = 每行2张大缩略图卡片。
- 关键认知：MV3 扩展的扩展后台 fetch（带主机权限）才能绕过 CORS；content script/MAIN world 的 fetch（mode:cors）都受 CORS 限制，无法破解严格防盗链。
- 复检：单测 28/28、语法 17/17、manifest 合法。

## 追加：防盗链缩略图代理 + 弹窗自动授权（9-4 晚）

用户反馈「列表还是看不到图片、右键上传仍失败（Failed to fetch）」+ 红条（Photos Library API 未启用）。两个独立问题的最终修复：
- **弹窗打开即引导授权**：在 popup `boot()` 里先 `chrome.permissions.contains` 读 `<all_urls>` 授权态存入 `state.hostPerm`，未授权且已登录则自动 `ensureHostPerms()`（工具栏图标点击=用户手势，最可靠）；不再只依赖右键菜单/上传时申请（那些手势上下文在 MV3 不一定稳定）。
- **防盗链缩略图代理**：新增常量 `MSG.PROXY_THUMB`，SW 处理 `proxy_thumb`（用 Downloader 抓图→`U.bufToBase64`→返回 dataURL）。popup `buildRow` 在 `state.hostPerm` 时把缩略图换成后台代理的 dataURL，且用 IntersectionObserver 进入视口才触发（避免一次性抓几十张全图）；`proxiedThumbUrl` 带 `state._thumbCache` 去重。这解决了「列表显示为空白/裂图」（尤其是 jkforum 这类防盗链图）。
- **download 路径顺序**（downloader.js）：优先 SW 直连（hasPerm 时）→ content script → MAIN world；全部失败且无权限时返回 `{needsPerm:true}` 的明确提示。
- 关键认知：`<all_urls>` 主机权限是绕过 CORS/防盗链下载与展示缩略图的**关键开关**，弹窗打开即引导授权最可靠。
- 复检：单测 28/28、语法 17/17、manifest 合法。
